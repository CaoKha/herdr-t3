# The space panel is made of closable tabs

Supersedes the fixed Files/Review pages of [0011](0011-one-space-panel.md); revises the reading state lifecycle of [0015](0015-panel-pages-stay-independent.md). The directory breadcrumb is revised by [0018](0018-files-follow-t3-surfaces.md) to match T3: a directory tab opens from beside the file. The details popup is in [0019](0019-details-popup.md).

Following the surface interaction of T3 Code `09a54f01`, each space keeps a tab list, the active tab, open state and maximize state; the width is still one for the whole window.

- Each file gets its own tab; there is at most one generic Files tab and at most one Review tab. Opening a file from generic Files replaces it in place; if the file is already open, its tab is activated and the generic tab removed. Files with the same name aren't told apart, as in T3; when a name is truncated, the tooltip shows it in full.
- Adding, removing and changing tabs in the list are pure functions (`shared/surfaces.js`); `shared/panel.js` only stores them and lays out the layout. Each tab has an instance number `born` and a selection count `reveal`.
- Each mod handles releasing on close itself: when a `born` it has read is no longer in the list, it releases it. The panel doesn't write other mods' keys. Review's `review.shown` and `review` requests both carry `born`, so closing and adding again starts from the default range, and late reads and requests sent to an old tab have no effect.
- Selecting a tab increments its `reveal`; Files then clears search, expands ancestors and scrolls to the file (T3's revealRequestId); Files opening a file itself from the tree or search results doesn't count as selecting, and search is kept.
- All file tabs share one Files tree and one active preview, without copying the mod. Per space, only the three most recently shown file tabs keep their Editor/reading position; older tabs reread from the top, and closing releases at once. The host has no scroll position snapshot API; this is a bounded cache rule and doesn't affect reveal with a line number.
- Hiding keeps tabs and reading positions and leaves maximize; switching to another tab doesn't reset Review. Closing the active tab selects its right neighbour, or its left neighbour if there's none on the right; closing an inactive tab doesn't change the active one. Closing the last one collapses the panel; reopening shows Open a surface.
- Review reads the repository where the tab is working: the cwd of the tab's last active terminal, or the space folder when there is none, as T3's diff panel follows the thread's working directory. The `+` menu, the empty page, whether `cmd-shift-g` is available and the repository Review opens by default all go through `reviewRepo` in `panel.js`, implemented once.
- `cmd-t`/`cmd-w` in Files/Review go only through `mod:t3-files`/`mod:review` in `keys.json`: `t3-chrome.surface-menu` opens the menu below `+`, and `t3-files.close`/`review.close` close the active tab without closing the terminal. A mod's `on_key_down` doesn't handle these two keys. The tab context menu only manages tabs and doesn't change the position inside the Review tree.
- When tabs overflow, the wheel scrolls them horizontally, and ‹ › sit side by side after the tab strip as in T3, greyed out at the ends; horizontal scrolling shares `shared/scroll-strip.js` with the tab bar.
- Old records without `tabs` (the `page` of the fixed-page era) aren't migrated; the panel starts empty. When Herdr's built-in layout keeps Review in its own stack (with no `panel-empty`), only the page shows and no tab is stored.
- Insert in the file tree's context menu rejects paths containing control characters, keeping Copy path as the manual way in. Clicking paths in the terminal isn't done in the first version: the host has no link/click callback, and covering the terminal or polling its text is not used as a substitute.

## Considered Options

- **The panel clears Review's range record on close**: the panel would need to know Review's key names, tying a separately installed Review to this protocol too; Review would still have to block late writes, splitting one job across two places.
- **Tell same-name file tabs apart by showing the path in the tooltip**: T3 doesn't tell them apart, and the user chose to follow T3.
- **`cmd-t`/`cmd-w` only through the mod's `on_key_down`**: whether the host hands a key to bindings or to the view first isn't documented, nor verified with real key presses; if bindings go first, dropping the `mod:` section would make `cmd-w` close the terminal tab behind. The `mod:` section fires exactly once under either order, so the user picked it.
