# Files' structure and interaction follow T3 Code

Files' structure and interaction follow T3 Code's Files panel, while sizes, margins, colours and radii take this layout's tokens; the Files spec is in [specs/files](../internals/specs/files.md). Revises Files' standing toolbar and the forced same header/same states for both pages in [0013](0013-space-panel-pages-share-one-frame.md), and "the directory breadcrumb only locates in the tree" in [0017](0017-space-panel-surfaces.md).

- Generic Files shows the full-width tree directly; once a file is open, the content is on the left and the tree on the right in the navigation column. The file header is inline: breadcrumb, Open in, Preview/Code, Wrap, Tree; the last three are fixed slots, disabled when they don't apply (T3 hides Preview/Code and Wrap conditionally; this is deliberately different, and Tree doesn't move).
- **One tree, two pages**: Files and Review use the same row (`treeRow` in `shared/file-tree.js`), whose geometry doesn't change with the slots; there are no fold arrows, the directory icon's open and closed states show expansion, and all icons use the T3/Pierre glyphs. Review only adds the viewed box and the status letter. The Catppuccin icon pack is removed.
- Search filters the same tree by substring match; above 200 results, file-name hits and shorter paths are kept first. A search term is committed together with its results, so the UI never shows one search's results under another term; a term not yet searched shows loading.
- Single selection. Focus enters the tree only when the user starts from the tree or the breadcrumb; outside locating such as tab switches and commands only scrolls and selects, without taking the keyboard from the terminal.
- Menus (row menu, breadcrumb directory menu, Open in) are Files' own native popups, consistent with the rest of the layout's menus; like T3, only one directory menu is open, changing directory in place, with a Back row at the top going up one level, at most to the breadcrumb level it was opened from. The Open in menu is shared with the details (`shared/open-in.js`). cmd-w closes the menu first, then the tab.
- The directory breadcrumb opens a directory surface beside the file, keeping the original file and trail; navigating between directories keeps replacing in place. Directories aren't read as text.
- Reads only while the panel shows Files, and refreshes only with the window in front too (trees and files not yet read don't wait for the window); expand all goes up to 200 directories with 4 reads in parallel, and folding, single-directory actions and search invalidate the old expansion.

Kept read-only, with a shared tree per space and a bounded preview cache; no editing/saving added. T3's web document/media previews have no matching GPUI interface. Herdr has native drag_paths, so the Files tree can be dragged into the terminal, with the host handling paths and cross-machine rules; Insert stays as a separate clipboard entry point. The source and Markdown content areas stop left-button presses from bubbling, so the root element doesn't take native selection focus; `EditorState` only exposes language, text, font, font size, line number/folding toggles, readonly, soft_wrap and syntax colours, with no gutter background or height, and a window-wide `set_theme` would affect other controls, so the gutter can't fully follow T3; a self-drawn HTML prototype stalled on drawing a 40,000-line file and doesn't go into the product. The native readonly Editor stays, and the gutter is a known gap. Search uses substring filtering plus ranking (file-name hits and shorter paths first), there's no multi-select, the tree is focused only when the person starts from the tree or the breadcrumb, and the Review tree uses Pierre icons too. The item-by-item spec is in [specs/files](../internals/specs/files.md).
