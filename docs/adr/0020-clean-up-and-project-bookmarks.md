# Clean up reclaims idle terminals in one step; Projects are stored in t3.projects

A Herdr space stays alive through its live panes, and every terminal is a real process. The Inbox lists only agents that need you, so settled agents and shells waiting at their prompt left your attention while still holding memory. Before, the Inbox squeezed `Clear` into the Settled header, and when clearing the last pane it rebuilt an empty background shell with `tab.new` to keep the space alive: this mixed process reclaiming into attention grouping, and created hollow spaces the Inbox couldn't see.

We make reclaiming an action that doesn't leave the Inbox, and stop projects from depending on live terminals to stay alive:

- **Project (`t3.projects`)**: `t3-tabs` automatically records non-Home projects that have been opened `(machine, folder, name, named?)` (most recent first, at most 50). `New` (`t3-new-menu`) lists the Projects not yet open after the currently live spaces, and picking one calls `space.new` to wake it in place; a row for a Project not open (including records on offline/removed remote machines) can be removed from `t3.projects` with the `×` at the end of the row or `ctrl-d` on the selected row, staying in `New` and without touching live spaces or files on disk; live space rows show no process state or close control. Closing a whole space no longer loses anything, so there's no longer any need to take stock of which projects are still alive.
- **Clean up (`t3-tabs.cleanup`)**: the shortcut and the trash icon in the sidebar footer open its dialog, and the dialog is the confirmation, without opening any list first. Idle terminals fold into two separately expandable groups: `Settled` (top-level agents outside the current tab that the core has confirmed `settled`, with no busy sub-agent) and `Idle shells` (non-agent shells at `atPrompt`), each folded by default down to its count and the spaces that would close with it, and expanding lists names and program icons by space; they can all be closed in one step by the main button at the bottom (`Close all <n>` when both groups are present, otherwise `Close <n>`; `Enter` does the same), or closed one by one, staying in the dialog, by a group's `Close` or by a row's `Close` (or `ctrl-d`) on expanded rows. All `Close`/`Stop` buttons on the right sit in one fixed 54px column, so hovering doesn't reflow, and the first press (including `ctrl-d` on a row/card) acts at once with no second confirmation; `Esc` closes the dialog at once. Every close rechecks its targets with `scanCleanup`, and only tabs that lie entirely within the subset to close are closed with `tab.close` (`confirmed: true`); spaces left empty close with them. Each program left behind (Left behind) is a card naming its space and foreground process: clicking the card jumps there, and the card's `Stop` (or `ctrl-d`) stops it directly while staying in the dialog; text instead of `×`, because elsewhere in the layout `×` pops up a separate confirmation while a program is running, and one icon shouldn't have two outcomes. Counts and the spaces that close with them are computed live from the terminals still there; when closing everything together would empty extra spaces, the note at the bottom names them first, then names the two scopes skipped: the current tab, and programs in the current space. The name is Clean up throughout: what it reclaims can't be restored, so it's not called recycle bin or Trash; the trash can is only the icon. Left behind means it's still running, but its space has no agent at work any more (no unsettled top-level agent; snoozed ones count as working), and it's not the space you're in. When none of the three exists, only a notice pops up. Forgotten programs are found and dealt with here.
- **Finding terminals**: left to Go to (it already searches space names; typing a project name lists that project's panes) and the breadcrumb's space menu.
- **Inbox and Filter**: `Clear` is removed from the `Settled` header; `Filter by space` lists only spaces that currently have entries in the Inbox or are still in `scope`.

## Considered Options

- **A warm buffer that reclaims Settled terminals automatically**: rejected. Silently killing processes in the background would catch out people who want to scroll back through terminal history; reclaiming must be triggered and confirmed by a person.
- **Running: a popup listing all live spaces and panes, also handling space closing, the context menu and cleanup** (one version was built): rejected. It's a live inventory, not an action: jumping duplicates Go to, closing spaces duplicates the space menu, and it also lists agents that need you right now; the footer's count of live spaces doesn't tell you whether to act.
- **Background: list only settled agents and panes with no agent, grouped by space, as a popup or a sidebar mode** (one version was built as a popup): rejected. Going through real scenarios one by one, none needed it: reclaiming is done in one step by Clean up, and the confirmation surfaces forgotten programs along the way; to get back to a program you remember its name and use Go to; to get back to a settled agent there is the Settled shelf. Opening a list before cleaning up only drags you out of the Inbox for one more step.
- **Add a `Spaces` or `Terminals` shelf at the bottom of the Inbox**: rejected. The Inbox is organized only by attention.
- **Put live state and closing into `New` or `Filter by space`**: rejected. It pollutes the single action of each: "create new" and "filter cards".
- **Add other spaces to the breadcrumb's space menu**: rejected. Its meaning is "what's in the current space".
- **Grey out the footer button when there's nothing to close**: rejected. Whether a shell is idle has to be probed with `hc get`, and the footer can't probe on every frame; if there's nothing after pressing, a notice pops up.
- **A confirmation with only a paragraph of text naming what will close and what's still running** (one version was built): rejected. With many names it can't be read, and a forgotten program spotted in it can't be dealt with on the spot; you'd have to open Go to as well.
- **List every program still running outside the current tab as a card** (one version was built): rejected. The system only knows it's running, not whether you're still using it; a `btop` you're watching or a dev server you're using would come in too, while this dialog means "these can be thrown away". Changed to list only programs whose space has no agent at work; a dev server left open during manual testing can still be listed, but isn't cleared by default.
- **List only programs not looked at in a long time**: rejected. It needs a time threshold, and programs that run in the background long-term and truly don't need looking at would be misjudged.
- **`×` on cards to stop** (one version was built): rejected. The same `×` pops up a separate confirmation in the space menu while here it stops directly from the card; changed to the text `Stop`, so one icon doesn't express two outcomes.
- **Closed terminals can be restored**: rejected. Once a process ends it's gone; restoring agents would mean recording a session ID per program and resuming, costing far more than it gains.
