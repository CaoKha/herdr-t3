# Host limits in the layout implementation

Read this when changing render/timers, keyboard/hover, measuring/scrolling, Review text or wallpaper conversion. The visible spec and acceptance are in [RECIPE](../../RECIPE.md); sizes/colours follow [t3-tokens](t3-tokens.md), cross-frame data and files follow [storage](storage.md). This file records only limits you can't see from API signatures; it doesn't copy those two files' tables or archive old versions of RECIPE.

## Render only builds views

Herdr refuses, during a draw, operations that would request another draw: `cx.notify()`, `cx.new()`, `cx.focus_handle()`, `InputState.new()` and the like throw, keep the old frame and report `This view could not be re-rendered`. Review's first read and `VirtualListScrollHandle.new()` must also start in `cx.timer.after(0, …)`; a read started during a draw may not return until the 30s timeout. When a draw finds an Undo request, a theme change that needs a reread and so on, it schedules a 0ms timer first and acts after the draw.

`scripts/render-guard.cjs` preloads these constraints in the fake Herdr. `scripts/check.sh` also runs checks inside the installed app home, because some tests look at official icons; type checking uses the `tsc --noEmit` arguments in the script, not the git-ignored `jsconfig.json`, since the default config the official check generates doesn't suit these mods.

In Herdr 0.1.16 `checking()` is true for the whole check; the check still runs `init()` and the first draw, and `exec`, `hc` and `writeTextFile` still run too, so host interception can't be relied on. So in-memory setup (inputs, focus, lists) and full render run as usual, and entry points that act on the host or the machine (probes, reads, cache writes, exports, screen queries, label commands) are skipped in check mode. `shared/check-checking.cjs` records these entry points' commands and writes: in check mode they must be empty, in real mode they still clean up and export; the real `herdr-app check` then covers drawing.

The first row computation can end Settle / Snooze; in check mode `shared/labels.js` returns not-written directly and sends no label command to core.

A native popup's automatic height can't take `overflow_y_scrollbar()` directly: a root scroll container with only `max_h` and no definite height measures as 0, and the overlay, though registered, is invisible. Details measures the height with a non-shrinking content layer in `on_size_change`, then gives the outer scroll viewport an explicit height (at least one row of controls, at most 420); it notifies only when the height changes, and a 0 measurement doesn't overwrite a valid value. Neither `herdr-app check` nor `status.errors=[]` verifies actual layout; a whole-window screenshot and non-zero layout sizes are still required evidence.

## Hidden copies and resident entry points

A mod in a hidden stack child/column doesn't draw and doesn't receive `<mod>.<command>`; timers started after launch keep running, but before the first show they haven't started yet. Inbox/Agents row computation is independent of `render()` and is also called by a per-second timer, and only the current mode writes agent order; when Agents comes after Inbox, its per-second timer only updates status history and drops pins and folds of finished agents (`observe`), without sorting or grouping. Commands/Snooze that must always work are maintained in the root-floating, visually empty `t3-tabs {part:"keys"}`; they can't depend on the tab strip, which a widened panel can hide.

The sub-agent layer (`t3-pane`'s `kidsMenu`) reads `terminals()` fresh on every draw to build the tree (`kidTree` in `shared/tree.js`), keeping no snapshot; a snapshot would only make status arrive a second late. The per-second timer only refreshes durations, and closes the layer when all descendants have ended. `tree.js` builds an index only once per `terminals()` list (`WeakMap`: live terminals grouped by parent address, terminals by address, each address's descendants once asked): Herdr returns a new list on every call, so keying by the list object never goes stale; the index is reused only when the same list is passed down within one draw. Filtering the whole list level by level is O(agents × terminals), and with 5,000 terminals one draw of Tabs/Agents/Inbox gets `interrupted` in QuickJS; with the index it takes about 19ms. The fake `terminals()` in checks must also return a new array every time; mutating the same array in place reads a stale index. `shared/project.js` likewise builds an index only once per `panes()` list, and keeps the space icons and fonts read in this draw alongside it: callers pass in the list they read in this draw, and the fake `panes()` in checks also returns a new array every time.

The panel's `surface-*` copies decide in render whether Review can read (`probeReview`, returning early if the key is unchanged), with no periodic timer: hidden copies' timers don't stop, and 250ms polling would keep reading host lists while the window is idle.

`nav()` in `t3-tabs/main.js` gives strip and keys the same navigation. keys can advance on its own; when strip takes the model and tab shortcuts take the order, `navigation.js` advances first itself, without depending on draw order. `check-navigation.cjs` replays the same observations interleaved. `shared/sidebar.js` looks for `sidebar` and `sidebar-lists`; a missing stack isn't treated as Lists, since a standalone-published mod may not have the whole layout.

When the layout jumps to a known space, the resident `t3-tabs` keys copy prepares the target's work column frame, tab row height and panel before the select command. Host commands queue, and `spaces()` may still point at the source. It waits for the target only while it still observes the source; once it observes a third space, it restores for that third space. Who owns the open and widened states: see [storage](storage.md).

`space.new` comes with a shell. When Home is created cold, the space and the configured mod tab are created in the background with `focus: false`, and it switches in only after confirming that tab already has the target mod pane. If the window had no space before, Herdr shows the first space created, even with `focus: false`. Home's identity and creation bounds: see the [Home spec](specs/home.md).

## Hover and lost leave events

A tab's `×` is decided by the actual pointer position. The top bar sits right at the window edge, and when the pointer moves in quickly from above and stops, extrapolating by speed misjudges it as having left. Herdr keeps only the last `on_mouse_move` callback per element, so `shared/tab.js` records tab bounds and dispatches drag sorting in the same callback.

Herdr may drop a leave when the last known mouse position still falls within the element's previous frame, while GPUI has already recorded it as left: the first move out of a row after a key press, dragging out while held and then releasing, and leaving the window can all leave a hover behind. While a tip/details is showing, `pointerGone` in `shared/tip.js` compares `mouse_position()` with the element box every 100ms; controls with no card that are only lit by hover use `hoverKept`. On macOS, once the pointer leaves the window no more moves are sent; if the pointer has stopped and two more steps along its last step would cross the window edge, it counts as gone. A drag also ends when the window deactivates; it can't just wait for a release that never comes.

Tooltips use a `Popup` that manages its own timing: a `HoverCard` stays open while the pointer rests on the card, and a transparent popup still blocks input underneath. Each open gets a new id, and the size is reported only on that id's first layout; it fades in after layout. `Popup` doesn't flip automatically; places like the top bar pass `below` explicitly. The official `.tooltip()` takes only a string and host styling, and can't give this look.

## Keyboard, close keys and menu chains

Keyboard mode is managed by `shared/focus.js`; each copy's close calls `stopsEnd`. The first copy of a run clears crash leftovers through `globalThis.t3FocusRun`: Herdr currently shares one JS context across all mods but doesn't promise it, and `sessionStorage` is per copy. A copy not in keyboard mode that sees a plain stop pressed must end the old mode before the press takes focus. Menus inside Inbox keep the mode only while they really hold the keyboard. The Files tree takes focus only when the user starts from the tree, the breadcrumb or Locate; outside reveals like tab switches and commands only scroll and select, and don't take the keyboard from the terminal. The tree row focus ring appears only after arrow keys and the like have been pressed in the tree, not on click.

Since 0.1.14 Herdr handles close keys bound to `tab.close`/`pane.close` itself, but the layout binds them to `t3-tabs`, so every popup/dialog needs its own `mod:<name>` override of the four keys to `overlay.close`. The two panel pages have their own close override (Files' layer menus also go through `t3-files.close`, which closes the menu first and the tab only when there is no menu; the gate accepts `<mod>.close`); for a mod that can be both docked and a layer, when the keyboard Tabs to the docked copy it also catches these four keys, and then closes nothing. The repo's gate checks the overlays it opens itself; recheck Herdr's built-in layer list when upgrading.

Clicking the button of an open popup, the outside press closes the layer first and only then does the click reach the button; `close()` writes the time, and the button avoids reopening immediately through `shared/trigger.js` (`trigger()`/`opener()`, internally `pressed` + `justClosed`); each layer uses its own key, so with one open, clicking another's button still opens it. Layers inside Review pages are the same: an outside press that closes one writes `review.<name>Closed`. Menus of `t3-menu`, Files, Review and details register through `shared/popup-menu.js` who hangs under whom (when a submenu closes, its `close()` hands the keyboard back to the parent; Herdr forbids `focus()` in render/layout, and `scripts/render-guard.cjs` makes checks fail when focusing there): closing also closes descendants, choosing an item closes the whole chain, and submenus open beside (`openBeside`); a submenu closing writes its own `<mod>.submenuClosed` (details' Commits writes `t3-actions.menuClosed`), which the parent reads on render to redraw and take back the keyboard (`subGone`). Placement below a button always uses `hang` from `shared/trigger.js`. Submenus inside Review pages reuse the hover intent/arrow key rules from `shared/submenu.js`. The Snooze `Popover`'s Enter/Space must be bound in the panel context that holds the focus handle, otherwise the host binding only closes the menu without choosing. Scrolling lists use `shared/list.js` to sync pointer/highlight/scroll; wrapping another scroll container falls behind key presses.

### macOS menus bypass layout rules (Herdr 0.1.16)

The macOS menu's `File > New Tab`, `File > Close Tab` and `Window > Go to Tab…` call `tab.new`, `tab.close` and `mod.open:picker` directly without checking `keys.json`, so they skip T3's Home rules, close confirmation and `t3-picker`: New Tab can open another tab inside Home; Close Tab closes a tab that isn't the last and still runs a program directly (the last one becomes the core `space.close`, which may still show a native confirmation); Go to Tab opens the official picker. Key bindings still go through T3; that a menu shows the same shortcut doesn't mean both behave the same.

This is a host limit: core commands take priority over mod commands and can't be overridden; menu actions bubble from the terminal's host element without passing through the mods in each block, and `on_action` can't catch them either. Bindings and dispatch are per Herdr `src/macos.rs` and `src/window.rs`; the command behaviour has been replayed in a separate demo window, real menu clicks are unverified. No emulated interception layer goes into the layout.

## Size, scrolling and reflow

Truncation tips all go through `shared/measured-text.js`: the shown text measures the container, and a zero-height copy without truncate measures the natural width, both with the same font/weight; it updates only when the layout width changes. Actions, the computer name and surface tabs show a tip only when truncated or folded to an icon, the split arrow has only an aria-label, and breadcrumb/file tree rows get no tooltip. T3's existing status/Woke action tips are kept.

`on_size_change` returns pixels multiplied by zoom; layout resize uses logical pixels, so divide by `settings().zoom`. Actions/end set their own block widths, and `tabs-row` can't be dragged. Compact measures the work column in `bar-measure`, which isn't affected by tab control widths; measuring in the tab area would open and close repeatedly as controls shrink. macOS traffic lights are in unscaled screen points; file hot-reload compensation and concurrency-safe writes: see storage.

Since Herdr 0.1.15 ordinary scroll areas can show a given direct child with `track_scroll(handle)` and `ScrollHandle.scroll_to_item(index)`; don't put `pt`/`pb` directly on an `overflow_y_scroll()` container (especially the Inbox list, which has a `flex_1()` spacer child), or GPUI computes an extra scrollable margin of `pt + pb` that wobbles up and down even when nothing overflows; use `flex_none()` spacer blocks at the start and end for vertical padding instead. The tab strip is clipped by `tab-scroll` and offset by `tab-strip.ml()`; a zero-height full-name copy measures the full width, corrected only when active/room changes. The manual offset controls both the wheel position and the fades at both ends. Search/trees use a controlled virtual list. The Agents list is windowed above 50 rows (`mods/t3-agents/main.js`): row heights come from the item heights and y that `planMotion` already has, only rows in the viewport plus two above and below are drawn, the wheel moves it itself, and `leavingRows(view, top)` follows the offset; before the first measurement it draws at a height of 800. The host's `v_virtual_list` rows can't hold handlers, so it isn't used. The cost: when windowed, Tab only reaches rows already drawn. With 200 agents and 5,000 terminals, a windowed frame is about 427 elements, a full draw 13,219.

The navigation column doesn't use the host's `h_resizable`: it keeps each block's size by id and scales proportionally with the page, so when the panel widens it scales wrongly for a frame before snapping back. The shared `shared/nav-column.js` draws its own edge; dragging changes only this page and saves only on release. `holdWidth` shares the algorithm but each page has its own state: it reflows after the width is stable for 300ms; before that Files keeps the old Editor width and clips, and Review keeps the old wrap column count. An Editor's soft wrap config is taken at creation, so after toggling it is rebuilt outside the draw. When a Files file over 16KB is rewritten or Wrap is toggled, a plain-text Editor is built first, and highlighting is swapped in by `colorLater`'s `cx.timer.after`: each postponement takes a new stamp, and an old timer is void when it fires; if the file isn't showing when it fires, it doesn't swap, and render schedules again when it sees the file still unhighlighted, so hidden pages don't highlight. Files/Review refresh and cache lifecycles are defined by storage.

In Herdr 0.1.16 `watchFolder()` returns a cancellable Promise (`FolderWatch.cancel()`): cancelling ends this wait with an empty array and releases only this call, without affecting other subscribers to the same folder. Spaces keeps a token and the current pending wait for each local repository; when a repository is unused or the view closes, it removes the token and cancels, and a late Git read doesn't publish a repository that has gone. The standalone Review bar releases the same way when its current folder changes or it closes; an old event, even one waiting inside `check-ignore`, can't change a new token's state. Spaces also has a 60-second foreground fallback, the standalone Review bar 10 seconds; T3's toggle mode doesn't start count watches. The Files/Review panels poll per ADR 0015; switching to event refresh needs its own verification.

## Outside closes and unread compensation

When the layout closes something itself, it leaves first and then deletes; when a program ends, Send back runs or a space disappears, there is no time, and Herdr has already shown the neighbour and marked it seen in the same step. `navigation.js` records a debt only for an agent that was unread in the previous frame and was brought out only by this automatic selection; once it leaves view and seen comes back, it writes `herdr.seen=<turn-1>` (the official Mark unread), also returning a wrongly cleared Woke. If it stays in view for a full 3s, it really was seen; a failure warns only the first time and retries while still valid. This is remembered for this run only, with no guessing across restarts; how labels are written and who owns them is up to storage and `shared/labels.js`.

## Review text and tree

`rows.js` takes its width table from `vendor/char-width.js` (generated by `scripts/vendor.sh` from get-east-asian-width and Unicode mark/default-ignorable): wide/fullwidth 2, combining/joining/variation and joined characters 0, the rest 1; line breaks avoid combining and joined characters. It measures the code font's `0` and a CJK ideograph separately: a fallback CJK font isn't necessarily twice the Latin width per character, and two columns are used only before it has been measured. When rows arrive, the read job's `clipRows` builds cumulative column widths; a width change only computes row counts, by division for ASCII and binary search over the cumulative widths for non-ASCII, and actual splitting is done only for visible rows, never recomputing the whole diff on every draw.

Group counts (`tabStats`) are computed when reads/viewed state change, not walked again on every arbitrary Herdr redraw. The tree's folder row check state uses `underFolders` in `files.js`: after building the tree it builds "folder → files under it" once per group, invalidated with `treeOf`; filtering the whole group per row is rows × files, and showing indent lines on hover would trigger it too. Files search's `rankPaths` keeps only the top 200 and yields every 5,000, like `filterPaths`: ranking 110,000+ hits in one go gets interrupted. The files' natural order is normalised once on read, so diffs, row requests and j/k share one order. Subgroup paths use `group:<key>/src` to keep same-named folders apart; subgroups can't be merged into a lone folder. The sticky file header needs a `background` underlay first, so a translucent selected doesn't show code through; unchecked colours first expand short hex, then scale the original alpha, and borders keep the original colour.

## Wallpaper conversion, not the user lifecycle

`extras/mods/asciicn-wallpaper/ascii-art.js` is the only implementation that draws images into `.ans` at runtime and converts `.ans` into tiles; built-in pictures' tiles are fixed in `scenes/`. asciicn has no CLI/package. `imagePlan` computes the cover rectangle from 96-cell rows, 16–480 columns by aspect ratio and a cell aspect ratio of 0.5, and the draft is Braille's sampling grid (columns × 2, rows × 4, the finest step of any mode): produced directly by the system scaler (sips, ImageMagick `-resize`), read back once as BMP base64, with decoding that supports 24/32-bit and both row orders. `sampleImage(pixels,style,plan)` averages whole-block areas over the draft to get the other modes' grids (Braille uses it as is); RGBA is reused within the draft, without rereading the original. It doesn't do 4× supersampling then block averaging in JS like the website: per-cell glyph agreement is 87–99% (lowest for Braille), no difference is visible across the picture, and picking an image to preview is 5–10× faster. Glyphs and per-cell RGB from the same sampled RGBA must still match the real `mapTones` cell by cell; a hand-copied algorithm can't serve as the oracle.

The host's `exec` silently drops stdout beyond 8MiB; the largest grid draft is 960×384, a BMP about 1.1MB, base64 about 1.5MB, read in one exec. `decodeBmp` still accepts chunked text. Before allocating RGBA it checks the header, size and that the decoded bytes are complete; RGBA conversion yields every 4096 pixels, not in fixed 64-row chunks (a large wide image would stall nearly 200ms in one step).

Dots/Blocks sample 1×1 per cell, Quadrants 2×2, Braille 2×4; autoLevels clips 0.5% at each end, and tones are clamped to [0,1]. Dots has **6 steps** (blank plus 5 dots), thresholds 0.1/0.3/0.5/0.7/0.9; Blocks has 5 steps, ` ░▒▓█`; both packed glyph kinds light only when strictly above 0.5. Per-cell colour averaging keeps upstream gradeRgb's default floating-point maths and Uint8ClampedArray's round-to-even. Colour takes the nearest VGA16 slot in OKLab, not RGB Euclidean distance or 6 hue buckets; opacity is 8 steps by HSV value. The full canvas and blank margins are both kept, never cropped to content.

Characters use SVG, not text: host text swallows spaces/newlines, and fonts may ligate `##`. Geometric glyphs follow upstream's glyph, and other characters are approximated by darkness bars (Classic/Dense wait for glyph support). The cell aspect ratio is the header marker's 0.5 (see storage). Tiles are cut at 40 cells, matching the tile files of built-in pictures in `scenes/`, and compositing joins them block by block into one image. The sampling, tone and mapping generators yield per chunk; the caller batches cheap yields within a 6ms budget, then lets input/paint run; cancelling ends the generator before the next chunk. Switching modes first draws the selection and loading mark immediately, and a separate generation folder keeps late writes from polluting the new scene. Each drawn mode (characters and composite) stays in the draft per mode, so switching back recomputes nothing; a failed draw falls back to the last drawn mode.

The wallpaper has one draw path: tiles are composited with theme colours into one SVG (`picture` in `ascii-art.js`) and handed to native `image()`. It doesn't use `svg()` per tile: the host's SVG mask cache key includes the draw size, so every new size from switching, changing height or Zoom parses and rasterises all tiles synchronously in the draw frame (measured 50–570ms). `image()` rasterises once on a background thread, after which the GPU scales the same texture, so dragging, Zoom and arrow keys only change geometry. Opacity goes on `stroke-opacity`/`fill-opacity`, not `<g opacity>`: the latter needs offscreen compositing and is about 4× slower. `image()` has no load-complete callback, and a new path's image is empty while it rasterises in the background: when the theme changes, the same picture keeps the old path until the new image is made and loaded; the same applies when changing pictures (see the next paragraph). The theme can only be read in render, so when render finds no image for the current key, it starts one composite with `timer.after(0)` (`pictureOf`, once per key), never writing files directly in render. GPUI rasterises an SVG `image()` at 2× its declared size (`SMOOTH_SVG_SCALE_FACTOR`), so the SVG declares the device pixels Home shows it at, and the texture is 2× device pixels (sizes, steps and redo rules in [wallpaper spec](specs/wallpaper.md) "Picture size"): with a texture only at device pixels, dots smaller than a pixel look clearly grey and blurry at 1x, and only 2× comes close to the original. Decoded images stay in the host cache by path (mods can't release them), so pictures seen this run and small images from before growing all stay. VM-measured footprint (the shown picture plus the other one preloaded, 900×560 window): a 16:9 photo 107MB at 1x, 289MB at 2x, about 700MB when always declaring 4096; a 2.5:1 wide Braille picture 335MB at 1x, 575MB at 2x, already wide when filling, so device pixels save less. There is no screen scale API for mods: `screenScale` asks NSScreen through `osascript`, matching the screen by the window's centre x (GPUI's window y is relative to its own screen).

Image loading and waiting. `image()` rasterises in the background with no completion callback, and its own `on_size_change` doesn't fire either (measured). But GPUI sizes an unsized `image()` only once it has the image, and the `on_size_change` of a div wrapping it does fire: `layers()` puts an unsized copy of the new picture in a 0×0, `overflow_hidden` box, and when the outer div reports a width above 0 it counts as loaded (`loaded`) and only then is the new picture swapped in; until then it keeps drawing the previous one (`held`). Layers use the image path as id, so a new picture is a new element and appears directly at its target opacity, with no fade-in. `loaded` keeps only the paths drawn this frame (the shown one and the warm one below), deleting the rest on every render: the host releases images no longer drawn, and switching back probes again (next frame reports the size if the cache is still there). Measured: keeping a path no longer drawn makes switching back to it count as loaded and swap in directly, while the host has to rasterise from the file again, leaving Home blank for about 0.8s. Home's first picture has no previous one to keep, so Home is blank until the probe reports.

Switching light/dark can't rely on "keep the previous one": the previous one was coloured for the old mode; a light theme's paper picture (dark ink) on a dark background is almost all black, the reverse is a white sheet, and waiting for the new image's conversion plus probe takes 0.5–1.9s (measured in a VM). So once the shown picture has loaded, `warm()` takes the other mode's theme colours from `settings()`'s `theme_light`/`theme_dark` and `themes()` (overlaid with `settings().colors`), makes that picture in the background, and keeps drawing it with the same 0×0 probe copy (`wallpaper-warm`): only by drawing it all the time does the host keep it, so it stays in `loaded`. In the render that switches, the key is already made and loaded, and the new picture appears in the same frame as the new background colour. The cost is one more loaded picture (the same size as the shown one, see above). When the window grows, the shown picture is made first, and only after it swaps in is the other remade at the new size, so two rasterisations don't slow down the one in view. Picking another theme (not in the current pair) still waits for its image, keeping the previous one meanwhile. Once the host releases an image no longer drawn, it can only reload from the file: when an old-palette file of the same mode is deleted, its key in `pictures` must be deleted too, otherwise switching back to that palette finds the path but no file, the probe never reports a size, and Home stays on the previous picture. A new picture doesn't fade in from opacity 0 (with the previous one removed in the same frame, Home would go blank for a frame, then dim for a few), and the previous one isn't kept underneath either (transparent-background dot patterns would overlap).

Wait indicators all go through `track(key, on, cx)`: timing starts the first time render sees a wait, nothing shows if it ends within 150ms, and once shown it stays at least 300ms; a draft's wait keys carry the draft id and are cleared with it on Cancel. Image read progress comes from `readImage`'s callbacks at the end of each step (reading the image fills the first half of the bar, the first draw the second half), not from estimated time.

No progressive preview: showing the read photo first and then swapping to the dot pattern makes the style jump, for only 0.25–0.45s earlier; when switching modes, the previous mode's picture is the rough preview, and lowering resolution doesn't save the character-to-tile time.

Framing input (`framing.js`). A wheel event's `delta_lines` appears only on notched wheels (macOS `hasPreciseScrollingDeltas == NO`), not on trackpads or the Magic Mouse; that tells them apart: with `delta_lines`, vertical zooms (doubling every 6 notches) and horizontal-dominant pans; without, it pans; with ⌘ or Ctrl it always zooms (doubling every 200px). Zoom anchors on the pointer: `zoomAt` first finds the proportional position on the picture of the point under the pointer, puts it back under the pointer after zooming, then clamps the alignment ratio to [0,1]. macOS momentum scrolling has no separate phase and still arrives as `moved` after the fingers lift: after `ended`, consecutive events less than 100ms apart are dropped, and `started` or a pause ≥100ms resumes. gpui-kit doesn't expose GPUI's `PinchEvent` (`on_pinch`), so ⌘ plus two-finger scrolling stands in for pinching. The framing card floats over the canvas and the host doesn't occlude: the card's own `on_mouse_down`/`on_scroll_wheel` call `stop_propagation` first, so the canvas below doesn't start dragging or zooming; scrolling on the Zoom row zooms around Home's centre. `on_drop` has no drag-over event, so a drag in can't be highlighted.

The `+` menu is a popup copy this mod opens with `props.menu = "add"`: it has no Home draft, so Choose image… goes back to the Home that opened it through `run("asciicn-wallpaper.add:<token>:image")` (`nextCommand` is sent to every copy, and the token only matches the open it made itself); opening the folder runs directly in the menu. The menu's `close()` stamps the `asciicn-wallpaper.menuClosed` timestamp, and `+` uses the shared `trigger.js`, relying on it to know a second click means close. So keys.json needs a `mod:asciicn-wallpaper` section; when the Home docked copy has focus these keys are caught too, and then nothing closes.

The native chooser goes by `window().platform`, without macOS `activate` (about 2s extra wait) or `default location` (Downloads asks for folder permission, which is also why the Downloads folder isn't watched). The Windows menu doesn't list the two file-picking items, relying on drag-in and the folder. EXIF orientation: `sips -g` reports the stored size, not the orientation; `-z`/`-c` work in stored orientation, and the orientation tag is applied only when writing BMP. So macOS reads Orientation through ImageIO with `osascript -l JavaScript` (treated as 1 if unreadable); for 5–8 (sideways) it plans by the upright width and height and swaps the width and height given to `-z`, and the written BMP is already upright; mirroring and 180° for 2–4 are also done by writing BMP. It doesn't first convert the whole original to an upright BMP (about 0.57s for 48MP). When one sips call does both `-c` and `-z`, a large crop gives the wrong size (very wide or tall images, e.g. 32×307 instead of the expected 32×384), so it takes two steps: first scale the whole image so the crop area is exactly the grid, then `-c` the grid out of the small BMP. On Linux every `convert` carries `-auto-orient`, and sizes are read through it too. A light theme is `settings().dark === false`; paper inversion is `PAPER` in `ascii-art.js`: the ramp is read backwards, quadrant/Braille masks are complemented, and tone steps go by darkness (1 − lightness), not HSV value. Paths, cache keys, chunked atomic publishing, concurrent invalidation and cleanup conditions for import/draft/save are maintained only in storage; read it before changing them, and don't write a second set of rules here.
