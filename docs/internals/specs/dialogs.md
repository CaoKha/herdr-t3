# New, Go to, Actions and dialogs

Geometry and rules of the command popups (`t3-new-menu`, `t3-picker`), Actions (`t3-actions`), confirmations and Layout Settings. The [RECIPE](../../../RECIPE.md) says what they do; dialog and palette tokens are in [t3-tokens](../t3-tokens.md) "Components" and "Not possible".

## New and Go to

- Top-centred popups, offset 96 (t3-tokens "Not possible"), 576 wide, content-sized up to 420, radius 16, 1px border, `shadow_2xl`. Content shows from the first frame.
- Rows 48: 20px title line and 16px second line, radius 4, 6 vertical padding.
- A ruled footer with 20px keycaps (radius 4, 12px medium).
- Go to has a borderless 36px search, 6 above and below. New's list caps at 285, Go to's at 313; both scroll with the keyboard highlight.

### Go to

- `cmd-p`. One row per pane: agents, shells, programs and mods; never terminals without panes, never Home.
- Order: recent panes newest first, then the current space, the current machine, the remaining space and tab order; the current pane last. Up to 30 live panes are remembered from every navigation route (`t3-tabs.recent`). It opens on the previous pane, so `cmd-p`, Enter toggles back and forth.
- Row: space mark and shared pane name; beneath, program icon and name, remote machine, space and live sub-agent `+n`; state at the right.
- Searches space and machine, explicitly named tab, pane name, program name and key, and folder. Pane-name matches rank before metadata-only matches.
- Enter or click runs `pane.focus`, across spaces. `ctrl-d` closes through the same confirmation as other closes ([tab-bar](tab-bar.md#close-confirmation)).
- A highlight belongs to a pane, not its row number. Reordering doesn't change the target. If the pane is no longer in the results, clear the highlight and don't go or close. An edited query doesn't accept the old results: the first matching pane is selected when the new results appear.
- Footer: ↑/↓ Navigate, Enter Go, Ctrl-D Close pane, Esc Close; New tab in… opens New.

### New

- Live spaces first (current first, machines kept together), followed by remembered Projects (`t3.projects`) whose `(machine, folder)` is not already open; the second line is the folder, with the machine for remote ones; a remote folder is written whole, as `~` stands for this computer's home. Projects on a remote machine that isn't ready stay dimmed (`0.64`) and warn `Machine unavailable` (`<machine> is not connected.`) when picked while keeping `New` open. When both live spaces and remembered Projects are shown in the Spaces step, the top heading is `Spaces` and a non-selectable 28px `Projects` heading (`px(8)`, `pt(8)`, `pb(4)`, aligned at 16px from the popup edge) separates the sections inside the scrolling list (kept in view when moving onto the first Project); when only remembered Projects are shown, the top heading reads `Projects` with no in-list heading.
- Choosing a live space opens a new tab at its current place with `t3-tabs.new:<space>`, as every way of opening a tab does ([tab-bar](tab-bar.md#whos-in-view)); choosing a Project runs `space.new` with its `folder`, `machine` and explicit `name` when `named`. Live spaces show no process status or close controls here ([ADR 0020](../../adr/0020-clean-up-and-project-bookmarks.md)).
- Local live spaces and remembered Projects whose folder no longer exists on this computer dim (`0.64`), append `· Folder not found` (`ansi1`, 12px) to their second line, and show a `Folder not found` warning toast instead of failing silently when picked while keeping `New` open; missing remembered Projects can still be removed with `×` or `ctrl-d`. Remote entries are never probed on this computer.
- Dormant remembered Project rows (including dimmed offline ones) render a fixed right-end `micro` ghost `×` button (`Remove <name>`) and also accept `ctrl-d` on the highlighted row to remove that entry from `t3.projects` without closing `New`, touching files on disk, or affecting live spaces; live space rows and machine rows have no `×` and ignore `ctrl-d`. When any dormant Project is listed in the Spaces step, the footer adds `⌃D Remove` (macOS) / `Ctrl+D Remove` (elsewhere) after `Enter New tab`.
- Platform `1…9` pick numbered rows, labelled `⌘1` on macOS and `Super+1` elsewhere. When any dormant Project is listed in the Spaces step, live space rows reserve a 20px trailing spacer matching the `micro` `×` button so the shortcut labels align in one vertical column across `Spaces` and `Projects`; when no dormant Project is listed, the spacer is omitted and shortcuts sit flush right.
- New space in the footer and the Inbox and Spaces headers make the same choice: create immediately with only this computer, otherwise ask which machine. Candidates are this computer, the reported machines, and machines that still have a space. The active space's machine comes first; remote machines that aren't ready (including those no longer reported) are listed but cannot be picked.
- The footer opens the Machines step in place, with `← Spaces` to go back; a sidebar header opens at that step. Pressing the same header button closes its step; pressing the other switches steps. `cmd-n` creates on the active space's machine directly; New space shows that shortcut only when it creates directly. A sidebar installed without the New menu uses Herdr's native New space command.
- New tab uses the space's current place (first terminal's folder, else original folder), not always its creation folder.

## Clean up

- `t3-tabs.cleanup`: `cmd-shift-r` (`ctrl-alt-r`) or the sidebar footer's trash can. `t3-tabs` probes what's outside the tab you're on (latest scan wins when triggered again while probes are in flight) and opens Clean up, a `t3-actions` dialog (`actions: "clean-up"`, 512 wide, as the confirmation), with what it found: `settled` and `shells` rows (each `{ pane, terminal, name, space, spaceId, machine, program }`) and `cards` (`{ pane, name, space, spaceId, machine, program, process }`) ([ADR 0020](../../adr/0020-clean-up-and-project-bookmarks.md)). A lone pane in a named tab keeps `tab.name` (as the tab bar and close confirmation); an unnamed non-agent pane whose shared name falls back to its raw terminal address uses `foreground`'s process name when present.
- Settled (closes): core-confirmed settled top-level agents (`!isSubAgent`, so recovered agents whose parent exited count as top-level) with no busy sub-agent. Idle shells (closes): non-agent shells at their prompt (`hc get`: the foreground is the shell itself). Left behind (cards): non-agent terminals whose foreground is anything else, or that don't answer, in a space where no agent is at work: not the space you're in, and no top-level agent there unsettled (working, needing you, unread, snoozed or a non-sub-agent starting up before `agents()` lists it all count as at work). A program in a working space is in use and isn't listed.
- Drawn in Inbox's language (t3-tokens P5, P7, P9): the title is the act, `Clean up`, with no subtitle; the shelves carry the counts; the reason is last. Title 24 in, 12 above the body; body 16 in, shelves 8 apart, at most 420 high, scrolling.
- Shelf header, as Inbox's: 32px, 8 in, radius 6, a dim 12px label, its count in `muted`, and at the right a dim 12px note (`flex_1`, `min_w(0)`, right-aligned and truncated). `Settled <n>` and `Idle shells <n>` each have a 12px chevron and fold, folded by default; each shelf's note is `closes <spaces>` when closing that shelf alone empties spaces, and whenever `command` is present each header always renders a fixed 54px right-end `micro` `Close` button (`t3-tabs.cleanup-now:<serial>:settled` / `:shells`, 2px extra left margin after `closes`) regardless of whether the other shelf is present, closing only that shelf on the first click without closing Clean up. `Left behind <n>` doesn't fold; its note is `no agent at work` with no header button. Counts, `closes` and the footer label are worked out each frame from live panes: `Settled` requires a live unfocused pane whose terminal wasn't replaced and is still in `agents()` and `stillSettled`; `Idle shells` requires a live unfocused pane whose terminal wasn't replaced and hasn't gained an agent or sub-agent; `Left behind` requires a live pane.
- Settled and Idle shells rows, opened, as Settled's slim rows: 32px, 8 in, gap 8, radius 6, 1 apart, in five fixed columns so hover never causes reflow: 16px space mark at 40% until lit, 14px program icon at 60% (`programIcon` else `terminal.svg` for Settled; `terminal.svg` for Idle shells), truncated name (`muted`, `foreground` lit), space metadata (capped at 180px: truncated space name plus remote server icon and machine capped at 80px when remote, always visible), and at the right end (when `command` is present) an always-visible fixed 54px `micro` `Close` button on the `card` surface (label `Close <name>`, quiet `dim` at rest and brightening on button hover) that runs `t3-tabs.cleanup-now:<serial>:pane:<pane>` immediately on the first click (and `ctrl-d` on a lit row does too) while keeping Clean up open. Hover only lights the row with the `card` surface's 7%, space mark opacity and name colour (row hover tracked separately from `Close`'s button hover so moving between them never flickers); no element is added, removed or resized. Clicking the row closes Clean up and runs `t3-tabs.go-pane:<pane>`.
- Left behind cards, as Inbox's: 8 in, radius 6, 5 apart, a 4% `foreground` fill at rest (7% hovered), no outline. Line 1 (20, gap 6, dim 12px) stays fixed with zero hover reflow: space mark, truncated space name, optional remote server icon and machine, optional monospace foreground process (left out when the name already says it, always visible on hover), and at the right end an always-visible fixed 54px `micro` `Stop` button on the `card` surface (label `Stop <name>`, aligned in the same 54px column as every `Close` button above; quiet `dim` at rest and brightening on button hover): a word, not an `×`, because the layout's other `×`s open a confirmation dialog while a program runs. Line 2 (20, 4 below): the name (`muted`, `foreground` lit) and the 14px program or terminal icon at 60%. Hover only changes card fill and name brightness (card hover tracked separately from `Stop`'s button hover so moving between them keeps the card lit and `ctrl-d` targeting intact). A click closes Clean up and runs `t3-tabs.go-pane:<pane>`. `Stop`, or `ctrl-d` on the card holding the keyboard or under the pointer (as Go to's and the space menu's), immediately runs `t3-tabs.stop-pane:<pane>` (the pane, or its tab when it's alone there) while keeping Clean up open. `Esc` closes Clean up immediately. A row or card goes when its pane does; when all shelves empty, Clean up closes itself.
- Under the body, 12 below it and 24 in (level with the title), one dim 12px line (`clean-up-note`) naming both scopes: `Skips the tab you're on, and programs in the space you're in.` When both `Settled` and `Idle shells` are non-empty and closing both empties spaces not already emptied by either shelf alone, `Closes <spaces>. ` precedes it. Beside the buttons it wrapped and competed with them.
- Footer, 20 above, 24 in, only the buttons at the right, as T3's alert: `Cancel` and the single-step danger `Close all <n>` when both `Settled` and `Idle shells` are non-empty, or `Close <n>` when only one is (running `t3-tabs.cleanup-now:<serial>`; Enter does too, unless a control has the keyboard — the dialog itself is already the confirmation step); with neither shelf present, only `Done` (Enter closes it, unless a control has the keyboard). Confirming (`cleanup-now:<serial>`, `:all`, `:settled`, `:shells` or `:pane:<pane>`) rechecks each targeted terminal through `scanCleanup`, removes only the consumed targets from `cleanupAnswer` so remaining targets stay valid until cleared or replaced, and closes a tab with `confirmed: true` only when every pane in it is in the confirmed subset, so spaces they empty close.
- Nothing idle or left behind: no dialog, an `info` toast `Nothing to clean up` / `No idle or left-behind terminals outside this tab.`

## Actions

- Global, not per Project. The primary is the last run, else the first. `▶` repeats it; choosing from the menu runs and makes it primary; a row's gear edits; Add action creates. The menu is one, from the bar's `⌄` or Details' row, as T3's `ProjectScriptsControl`: no rule over Add action, a row's gear only while the row is lit or the gear has the keyboard.
- The standalone bar menu is 220 wide, aligned 1px past the chevron's right edge and 5px below its bounds; 28px rows with 36px for padding and Add action, capped at 420px. With no press bounds it uses the host's placement. The demo passes explicit window-pixel chevron bounds to `t3-actions.bar-menu:<bounds>`; it opens that same standalone popup, not a child of Details or a click on the default layout's Details button.
- Editor fields: required non-blank Name and Command; optional Folder, icon and Run in (Tab / Right / Down). Save is disabled until valid; Delete asks.
- Each run opens a new named tab or split: `terminal.open { argv: ["sh", "-c", command], name, place, folder? }`; the shell stays after the command exits.
- Without a Folder: the focused terminal's cwd, else a same-tab terminal's cwd, else the space folder; `~` expands.
- The list and last choice persist across restarts (`t3-actions.actions`, shape in [storage](../storage.md)).
- Shell aliases and functions need an explicit shell, such as `zsh -ic '…'`; plain Windows needs `sh` installed.

## Actions editor and confirmations

- 512 wide, radius 16, content-sized, padding 24, 20px semibold titles, 32px fields and buttons of radius 8; the shell is drawn by the mod (t3-tokens "Not possible").
- Confirmation titles wrap. Cancel comes before the named action (Close, Delete, Confirm). The action is red text (`ansi1`) on `raised`, not a red slab; the footer is bare, with no rule (t3-tokens "Deliberate differences").

## Layout Settings

- Opens from the footer's sliders or `cmd-shift-,`; invoking again replaces it. Esc closes an open select first, then the dialog.
- Deliberately Herdr's Settings, not T3: 880×620, a 190px left navigation with the `Herdr T3` title and a Home section, the right page inset 28/22, 14px row titles over 12.5px `dim` hints, dividers, 220×32 selects.
- Selects use 28px menu rows, no initial highlight, a check on the current item, arrows, Home, End and typeahead, Enter or Space to choose, Esc or outside to close.
- Home shows lists installed mods with `"home": true` in `mod.json`, read from the app home's `mods/` when opening; unreadable or invalid manifests are skipped. Sorted by title, else folder name; the selected mod stays listed even if it no longer offers itself.
- Choosing Home content refits Home at once and on arrival. Settings are live across instances and survive updates (`t3.settings`, defaults in [storage](../storage.md)).
