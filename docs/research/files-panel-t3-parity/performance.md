# Files 真实宿主性能回放

同一Mac、独立Herdr demo、默认侧栏、zoom1.1。fixture为24个顶层目录×6个项目×30个文件，加点文件与长目录链，共4,497项；展开非ignored树4,307行。不是用纯JS函数耗时代替原生绘制。`harness/fixture.py`生成本地目录；`native-probe.js`只包装产品方法记录，产品中没有这些探针。

## 先复现，再修复

原实现全部展开后立即Collapse：57ms时折叠，但旧异步读取继续，最终重新打开163目录，2,348ms才稳定。根因是展开循环只在await之前检查可见性，没有可被折叠作废的请求号。单目录紧凑链也有同样迟到写入；新增阻塞目录读取的回归先失败（expanded=1），修后为0。

修复共用`expand` ticket：Collapse、手动toggle、查询变化使旧请求失效；每次await后再检查。展开读取最多4路（T3同样4路），轮询刷新避开正在展开的树。焦点路径索引和目录统计跟树一起重建，不在每个原生重绘扫描全量行。暖重绘的字段访问数检查覆盖4k+行。

## 同fixture结果

原始日志未入库。`settledMs`含每25ms检查与至少三个稳定采样，因此小操作约有100ms探针底噪；它不是鼠标到光子的延迟。`renderMs`为本操作各次JS render总CPU时间，`layoutTailMs`为布局回调尾延迟，不是完整paint时间。

| 场景 | 前稳定ms | 后稳定ms | 后状态 / 工作量 |
| --- | ---: | ---: | --- |
| 展开中立即折叠 | 2,348 | 115 | 0重新打开；只有8个已派发读取结束 |
| 冷缓存全部展开 | 2,586 | 1,168 | 166目录、4,307行 |
| 三次虚拟滚动 | 117 / 106 / 112 | 114 / 112 / 110 | 每次0树重建、0文件读取；render总计3–4ms |
| 暖缓存折叠 | 118 | 109 | 28行，0目录重新读取 |
| 搜索 | 257 | 254 | 含200ms debounce，224树行（结果+祖先） |
| 清搜索 | 112 | 111 | 28行 |
| 切文件 | 136 | 124 | 64树行，文件头及原生Editor |

最终UI合并后再回放（原始日志未入库）：race113ms/0重开，冷展开1,225ms，滚动107/107/110ms且render每次总计2ms，折叠109ms，搜索254ms，清除114ms，切文件132ms。此时fixture多了两份源码候选probe文件，展开4,309行；不是隐藏样本差异。源码renderer的另一项大文件候选测试**失败**，不能与这些树性能混成“所有预览变快”；详见[源码报告](source-selection-and-gutter.md)。

没有测真实滚轮/鼠标/触控拖动；滚动通过同一虚拟列表的scrollTop状态回放。没有占用用户剪贴板、修改用户文件或启动外部编辑器。
