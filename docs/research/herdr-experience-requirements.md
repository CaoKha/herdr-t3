# Herdr 体验需求交接：详情、面板标签与壁纸构图

整理日期：2026-11-13。范围来自当前空间各会话的原始需求与已确认选择。本文按最终目标组织，接手者无需追溯会话、agent 分工或实施过程。

配套 [show-me 交互示意](show-me-experience-requirements.html)。**本文是需求依据；HTML 用来解释布局与交互，不代表 Herdr 已实现这些行为。**

A/B 以 T3 Code 的右上角控件与右侧面板为基础，对照快照 `~/my/tools/t3code` @ `09a54f01`（事实见第 7 节的 T3 研究）。规则后标「T3」表示与该快照一致；Herdr 有意不同之处集中在 B4。C 没有 T3 对应。

标记含义：**已确认**是用户已有的选择；**建议默认**是为交接补齐的实现建议，可在开发时按上下文调整；**待验证**是宿主能力或验收缺口，不是新增产品需求。

## 1. 整体目标与分工

把日常工作入口整理为三块：右上角详情提供当前工作上下文与 Actions；右侧 space 面板承载多个文件标签和唯一的 Review；Home 的图片导入在保存前完成构图。

| 工作包 | 用户得到什么 | 主要边界 | 依赖 |
| --- | --- | --- | --- |
| A · 详情与布局控件 | 两个明确入口；详情按需弹出，面板开关在窗口右上角 | 入口位置、三行详情、焦点、现有 Actions | 与 B 共同涉及面板头，先约定职责 |
| B · 动态面板标签 | 每个文件一个标签；Review 一个；可添加、切换和关闭 | 标签状态、文件选择、关闭与菜单 | 沿用第 4 节阅读规则 |
| C · 壁纸导入构图 | 新图片固定 Dots；导入时定位、缩放；Apply 后固定 | 导入草稿、构图、保存与失败恢复 | 可与 A/B 独立实施 |

这些工作包是交付拆分建议，不要求创建新的抽象层或重写已有模块。当前任务只整理交接材料。

## 2. A · 详情与布局控件

### A1. 布局与入口（已确认）

```text
面板关闭  主工作区标题                           [详情] [面板]
面板展开  主工作区标题 [详情] │ [文件标签…] [Review] [+] [放大] [面板]
面板放大                       [文件标签…] [Review] [+] [恢复] [面板]
```

- 详情入口属于主工作区；面板开关位于窗口右上角，打开面板后由面板头承载。
- 放大／恢复只在面板打开时出现；放大隐藏工作列，恢复回到并排。平台需要的原生窗口按钮继续在最右侧正确显示。
- 详情在所有宽度下默认收起，点击才打开原生 popup。打开和关闭详情不改变终端尺寸、分屏或 zoom，不预留常驻卡片的位置。
- 详情入口和面板入口是两种操作；详情内容不成为面板标签。
- 打开面板时收起已弹出的详情；关闭面板不自动弹出详情（T3）。
- 控件按 T3：按钮 28×28、图标 16、圆角 8、组内间距 4；2026-11-13 截图验收修正：详情用 SquareMenuIcon、面板用 PanelRightIcon，开启态是很淡的中性灰底，不用蓝色 accent。tooltip 在下方，显示名称和当前绑定的快捷键。详情 popup 锚在详情按钮下方右对齐，宽约 280。具体取值以 `docs/internals/t3-tokens.md` 为准。

### A2. 详情严格三行（已确认）

| 行 | 必须出现的内容 | 操作 |
| --- | --- | --- |
| 机器／目录 | 本机或当前 space 的真实远程机器名；当前工作目录 | 完整路径提示、复制目录；下拉复用现有 space 菜单 |
| Open in | 当前目录的可用打开目标：Finder 加本机已安装的编辑器（如 VS Code、Cursor、Zed） | 主按钮打开上次选择的目标，箭头列出全部可用目标并记住新选择（T3）；只有一个目标时不显示箭头 |
| Actions | 现有“上次使用的动作／下拉”按钮组；没有动作时 Add action | 运行、选择、新增、编辑、删除，显示完整动作名 |

机器属于 space 的事实；机器行不提供把现有终端迁往另一台机器的操作。远程目录不能交给本机 Finder：仍可复制路径，不可用的 Open in 显示原因。

宿主验证已确认：本机用 `open -Ra` 并行检测已装编辑器，`open -a` 打开；首版包含 Finder、已装的 VS Code／Cursor／Zed／Sublime Text。目标缺失回退 Finder，上次目标全局保存一份，约定见 `docs/internals/storage.md`。验证证据见 `host-capability-verification.md`。

2026-11-13 截图验收补充：三行都是 T3 整行按钮，不是左标签／右值表格。第一行 laptop＋单行截断的电脑名（本机 `scutil --get ComputerName`，远程用 Herdr 机器名）＋folder＋chevron；目录不显示文字，在 folder 图标 tooltip／右键复制菜单里。第二行应用图标＋Open in Finder／目标名，多目标才有箭头。第三行动作图标／名称＋split箭头，中线只在悬停时出现；空动作为 + Add action。没有应用图标时用本 mod 的通用图标，不允许空白。

详情不加入 Todo、agent 状态、space 概览、Review、Git 操作或底部终端。

### A3. 执行与焦点（已确认）

- 打开详情时确定来源 space／tab／terminal；目录优先当前终端 cwd，再同标签终端，最后 space folder。
- Actions 保留现有数据、图标、Tab／Right／Down 运行位置、显式 cwd 与编辑／删除确认。动作执行目录优先动作自己的 cwd，再用上述来源上下文。
- popup 获得焦点后，执行目标仍是打开详情时的来源。切换 space／tab 后来源失效，关闭并提示重新打开，不能在旧位置执行。
- Actions 子菜单的 Escape 先关子菜单，再一次关详情。执行动作或进入编辑器前收起对应弹层；关闭后恢复适当焦点。
- 点弹层外关闭详情；普通外点保留右侧面板。关闭 popup 的按键不能连带关终端标签。
- `cmd-shift-b` 改为切换详情；Inbox／Lists 通过原有侧栏按钮切换。`cmd-alt-b` 切面板、`cmd-shift-g` 切 Review；B 中面板内的 `cmd-w` 关闭活动标签，`cmd-t` 打开 `+` 菜单。
- 面板放大时通过详情快捷键进入，先恢复工作列，再弹出详情。Home 沿用其原有 Actions 上下文规则。

### A4. 验收

1. 本机与远程的三行内容、空 Actions 和多个 Actions 都正确；目录和动作运行位置可核对。Open in 记住上次目标，卸载或没有该编辑器时回退到 Finder。
2. 详情开关前后，终端的尺寸、分屏和 zoom 一致。
3. 嵌套 Escape、外点、动作编辑／删除和来源失效可回放，背后的终端不被误关。
4. 面板关闭／展开／放大只有一组正确的布局及平台按钮；装与不装 Review 扩展都能正常显示。
5. 默认侧栏宽度、窄窗、明暗主题下整窗内容完整。macOS 以外的窗口控件需对应平台验证。

## 3. B · 动态面板标签

### B1. 内容模型（已确认）

面板按 T3 右侧面板的 surface 模型工作：内容由用户添加、切换、关闭的标签组成，没有标签时显示启动页。它**取代**现在面板头里固定的 Files／Review 两页切换（ADR 0011 的「两者是面板的两页」）。不保留固定两页作备用，也不提供切回来的开关。

```text
space 面板
├── 标签条：[a.md ×] [b.js ×] [Review ×] [+]     [放大] [面板]
└── 当前内容
    ├── 文件标签 → 一个共用的 Files 视图，显示该标签对应文件
    └── Review   → 一个 Review 视图，在内部切范围、分组和 diff 文件
```

每个 space 保存自己的面板开关、放大状态、标签列表和当前标签；同一 space 切换终端标签时面板内容不变。面板宽度仍是整个窗口一份。

文件标签共享一棵 Files 文件树，不为每个标签各建树或 mod 副本。Review 在面板中最多一个；点击 Review 树里的文件仍是在 diff 内定位，不创建文件标签。

### B2. 操作规则（已确认）

| 操作 | 结果 |
| --- | --- |
| 打开空面板 | 标签条只有 `+`；内容区居中显示启动页（见 B2a） |
| `+ → Files` | 新增通用 Files 标签，只显示整宽文件树；已存在时切过去。已有文件标签时也是如此（T3） |
| `+ → Review` | 添加唯一的 Review，从默认范围开始；已存在时切过去，保留它的范围（T3） |
| 面板有焦点时 `cmd-t` | 打开 `+` 菜单；菜单内按 `F` 添加 Files、按 `R` 添加 Review（T3 的 `rightPanel.new`）。终端有焦点时 `cmd-t` 仍新建终端标签 |
| 在通用 Files 标签里打开文件 | 文件标签原位替换通用 Files 标签；文件已有标签时，删除通用标签并激活已有的文件标签（T3） |
| 再打开其他文件 | 每个不同文件新增一个标签 |
| 打开已存在的文件 | 激活已有标签，不重复创建 |
| 点面包屑里的文件夹 | 在共用文件树中定位，不开文件夹标签 |
| 点文件标签 | 切到这个文件；共用树展开它的祖先目录，选中它并滚到可见处，同时清空树的搜索（T3） |
| 点 Review 标签 | 恢复 Review 自己的范围、组、文件和阅读位置（T3：切换不重置） |
| 标签的 `×`／中键 | 关闭被操作的标签 |
| 面板有键盘焦点时 `cmd-w` | 关闭活动标签，不能关闭背后的终端 |
| 关闭活动标签 | 激活原位置的下一个标签 |
| 关闭最后一个标签 | 收起面板 |
| 面板开关 | 只隐藏／重新显示面板，保留尚未关闭的标签 |
| 关闭任一标签 | 释放这个标签的状态：文件标签的阅读位置，Review 的范围、组、文件和阅读位置。重新添加时从默认开始（T3：隐藏保留，关闭释放） |

### B2b. 从终端里的路径打开文件（已确认，待验证宿主能力）

**首版未完成：宿主不支持。** 验证确认没有终端链接检测或点击回调，不以覆盖终端或轮询文本替代；下列是未来宿主支持后的目标行为。

T3 的文件面板主要从 agent 回复里的文件链接进入。Herdr 的对应入口是 agent 在终端里输出的路径。

- 点终端输出里的文件路径，在面板里打开它的文件标签，规则与 B2 的「打开文件」相同：已有标签就激活，在通用 Files 标签里则原位替换。面板关着时先打开面板。
- 相对路径按该终端的 cwd 解析。带行号（`a.ts:42`、`a.ts#L42`）时滚到那一行，并短暂高亮。
- 指向文件夹时，打开或激活通用 Files 标签，并在共用树里定位到它。
- 只处理 space 工作目录内的路径；目录外的路径不经面板打开，保持宿主原有行为。远程 space 按远程目录解析，沿用 Files 的远程读取。
- 先在 demo 验证 `herdr-app` 能否接收终端路径点击，以及用哪种点击（单击还是 `cmd`+单击）。做不到时首版列为未完成，不用别的方式凑。

### B2c. 文件树右键（已确认）

T3 加文件树右键（PR #4054），是为了让浏览文件和给 agent 写 prompt 留在同一个流程里。Herdr 首版只放三项：

| 项 | 行为 |
| --- | --- |
| Reveal in Finder | 在系统文件管理器里显示该文件或文件夹；远程 space 不显示此项 |
| Copy path | 复制相对 space 工作目录的路径 |
| Insert into agent terminal | 把这个相对路径写进当前标签的活动终端的输入行，必要时前面补一个空格，不按回车（对应 T3 的 Add to chat）。没有活动终端时置灰，悬停说明原因 |

菜单在指针位置弹出，键盘可用 `Shift+F10` 打开，Escape 关闭且不传给终端。Review 的树没有右键，与 T3 的 Diff 树一致。

### B2a. 空面板启动页（已确认，T3 `RightPanelEmptyState`）

```text
[+]                                   [放大] [面板]

                Open a surface
          ▤  Files                    [F]
          ±  Review                   [R]   ← 不可用时置灰
```

- 没有活动标签时显示：第一次打开面板，或关掉全部标签后重新打开。
- 标题「Open a surface」下是居中的列表，最宽 320。每行高 32，依次是 16 的图标、名称和右侧的字母键提示；悬停或方向键高亮时用淡 accent 底色。
- 项目只有本布局支持的类型：Files `F`、Review `R`。没安装 Review 扩展时不列出 Review。已安装但当前不可用时（不是 Git 仓库、远程 space）置灰到 50%，悬停显示原因，不能触发。`+` 菜单对不可用项也这样处理。
- 启动页显示且面板有键盘焦点时，按字母直接添加对应标签，方向键只在可用项之间循环，Enter 执行。带 `cmd`／`ctrl`／`alt` 的组合键不触发；焦点在终端或输入框时，字母仍交给它们。
- 添加后启动页换成该标签的内容。

右键菜单：**Copy path**（仅文件标签）、**Close**、**Close others**、**Close to the right**、**Close all**（T3）。只剩一个标签时禁用 Close others，最右的标签禁用 Close to the right。批量关闭时最后关活动标签，避免面板闪出空态。

### B3. 交接补齐的建议默认

原记录没有逐项确定以下边缘行为；建议采用下面的最小一致规则，并在实现文档中明确。

- 关闭最右的活动标签时，没有右邻就激活左邻；关闭非活动标签保留当前标签（T3）。
- 新标签追加在末尾，只有通用 Files 被文件标签原位替换。
- 关闭最后一个标签后再按面板开关，显示空面板和 `+`（T3）。
- 隐藏面板时同时退出放大，重新打开时并排显示（T3）。切 space 再返回不算隐藏，恢复原来的放大状态。
- 标签外观按 T3，落地使用本布局 token：高 24、字号 12、圆角 6、最宽 144，左内距 6／右 8、子项间距 2。左侧 16px 槽平时显示 12px surface 图标，悬停／键盘聚焦换 12px ×（圆角 4、tab 面），右侧无关闭按钮；当前底 selected、悬停 hover、文字 foreground／dim。标题单行截断，tooltip 显示相对路径，同名靠 tooltip 区分。标签条左内距 8、项间距 4；+ 为 button() xs ghost（24 方／图标 14），紧跟最后标签并同条横滚，菜单左对齐、下偏移 6；布局控件固定最右。细节以 `t3-tokens.md` 为单一来源。
- 标签溢出时可横向滚轮滚动，两端出现翻页箭头，活动标签自动滚入可见区（T3）。
- 文件被删除或改名后，标签保留，显示读取失败的文件路径和工作目录，并提供「在 Files 树中定位」和重试（T3）。标签不自动关闭。
- 每个 space 只为最近显示过的 3 个文件标签保留 Editor 和阅读位置；更早的文件标签切回从顶部重新读入。关闭立即释放对应 Editor。此为 2026-11-13 实施确认：宿主没有读取／恢复 Editor 滚动位置的 API，因此采用有界缓存，不为所有标签永久持有 Editor；带行号的 reveal 不受此缓存规则影响。

### B4. 首版边界与待验证

首版不含 `cmd-shift-t` 重开、拖动排序、终端／浏览器／PR 标签或每个标签各自一棵树。

与 T3 有意不同（已确认，实施时不要改回 T3）：

| 主题 | T3 | Herdr |
| --- | --- | --- |
| 文件树 | 每个文件标签一份树实例 | 全部文件标签共用一棵树 |
| 面包屑文件夹 | 在文件标签上点：保留文件标签，另开该文件夹的标签；在文件夹标签上点：原位移到上层（`FilePreviewPanel.tsx:1172`，PR #15045） | 只在共用树中定位，不开标签 |
| 状态归属 | 按 thread 保存 | 按 space 保存，面板宽度整个窗口一份（ADR 0012） |
| 窄窗 | ≤980px 改成从右侧滑出的 sheet | 没有 sheet，靠整窗验收保证内容完整 |
| 文件树右键 | Open、Reveal、Open with、Copy mention、Add to chat | Reveal in Finder、Copy path、Insert into agent terminal（B2c） |
| 链接进来的路径 | 可打开项目外的文件和文件夹，各自配一棵以它为根的树 | 只处理工作目录内的路径（B2b） |
| 新添加 Review 的默认范围 | Diff 默认 Branch | Review 自己的默认范围 |

宿主的中键和右键事件、标签区域的键盘上下文需先在 demo 验证。标签列表和各文件阅读位置的具体持久化表示属于实现选择；下列只是原讨论的状态草图，不是必须复制的数据协议：

```text
t3.panels[space] = { open, wide, tabs: ["file:docs/a.md", "file:src/b.js", "review"], active: "file:src/b.js" }
```

### B5. 验收

1. 从空面板开始，加 Files、点两个文件、重复点第一个，只得到两个文件标签；之后再加 Files 出现通用标签，从中点开新文件时被原位替换。Review 始终只有一个。面板有焦点时 `cmd-t` → `F`／`R` 生效，终端有焦点时 `cmd-t` 仍新建终端标签。
2. Review 树内跳转不影响 Files 标签，切回 Files 恢复自己的文件；面包屑文件夹只在树内定位。
3. 回放当前／非当前／最右／最后标签的关闭，以及全部右键关闭项；验证中键与 `cmd-w` 的真实事件。
4. 隐藏再开、放大再恢复、切 space 再返回，都恢复对应状态；空面板仍可用 `+`。关闭 Review 再添加时回到默认范围，切到别的标签再切回时保留范围。
6. 终端路径点击：在 agent 输出里点相对路径和带行号的路径，打开对应文件标签并滚到该行；目录外的路径不经面板打开。宿主不支持时在交付中列为未完成。
7. 文件树右键：三项在本机／远程下按规则显示；Insert 只写入当前活动终端的输入行、不执行；Escape 不传给终端。
5. 长文件名和大量标签不会挤掉 `+`、放大和面板开关；默认侧栏宽度及窄窗整窗验收。

## 4. Files / Review 的共同约束

这里是 A/B 要保留的最终阅读模型，已由 ADR 0012–0015 收敛。接手时对照当前实现补缺口，避免照旧计划重做。

| 主题 | 最终要求 |
| --- | --- |
| 归属 | 窗口右侧一个 space 面板，跨终端标签；每个 space 恢复自己的内容 |
| 页面独立 | Files 浏览工作目录，Review 阅读选定变更范围；各自保留阅读位置、导航宽度与换行偏好 |
| 切页 | 手动选择目标标签和该页文件；取消 Open in Files / Open in Review 等隐式跨页请求 |
| 外框 | 相同卡片、常驻工具栏、左内容右导航；复用树行、菜单、加载／空／错误组件与主题样式 |
| Review 分组 | 工具栏下方整页一行组页签；含类别、名称、critical、增删数、文件数和已看进度；单组隐藏，多个组横向滚动 |
| 组筛选 | 选组后 diff 与文件树都只显示当前组；子组在树内；规则分组和 AI 分析分组都保留 |
| Review 范围 | 页内顶栏选择 Changes、Uncommitted、To push、To pull、Commits、Branches；上游相关项按真实可用性显示 |
| Review 能力 | 保持只读，保留 AI 分组／逐行说明、已看标记、整文件展开、大 diff 分批和现有阅读快捷键；阅读设置支持换行 |
| 菜单 | Commits／Branches 和设置子项采用侧向子菜单，支持搜索、键盘进退和靠边翻转；真实斜移需实测 |
| 文件树 | 单一当前文件；目录优先、忽略大小写的自然排序；共用紧凑行、目录压缩与键盘导航 |
| 本地／远程 | Files 支持两者；Review 以其现有本机 daemon 能力为界，不借本轮增加远程 Review |
| 文件预览 | 只读代码、Markdown Preview／Code 和图片；文本上限 1 MiB，远程图片上限 512 KiB；搜索按路径 |
| 生命周期 | 只在对应页面、space、窗口可见时读刷；本地通常 5s、远程 10s，Review 15s；显示时补读，大仓库适当放慢 |
| 资源 | 每页最近三个 space 保留完整数据，更早释放内容／Editor／diff 缓存，保留轻量阅读设置 |
| 监听 | 沿用可见时轮询；现有 watchFolder 的未决订阅不能可靠撤销，递归 watcher 不作为本次前置依赖 |

不加入选行批注交给 agent、GitHub PR 评审、stage／commit／push、文件编辑／新建／改名／删除或全文搜索。

## 5. C · Home 壁纸导入构图

### C1. 用户已确认的流程

```text
选择图片 ── 固定生成 Dots ── 构图预览 ── Apply ── 固定显示
选择 .ans ── 保留字符画法 ── 构图预览 ── Apply ── 固定显示
                                  └── Cancel ── 返回原壁纸
```

- 新图片固定使用第三种 **Dots**，去掉图片导入的 Braille／Blocks／Dots 三选一。
- 位置和铺放方式只在导入时调整，Apply 后固定，日常画面不进入拖动编辑。
- Studio `.ans` 保留原来的字符画法。移除图片风格选择不等于移除已有 `.ans` 的 Braille／方块字形渲染。
- 已保存壁纸与内置画保留；日常仍可切换、添加、确认删除。
- 控件按钮在各状态下位置固定：内置／可删除壁纸、首尾／仅一张、长短画名、导入／转换／应用中、错误、删除确认、Studio 指引展开及明暗主题都不能挪动同一个按钮。不适用的动作保留槽位并置灰或说明原因；临时 UI 不挤动其他按钮。构图面板的 Reset／Cancel／Apply 同样固定槽位。
- 直接把 `.ans` 放进壁纸目录仍按默认构图载入，不自动弹出导入预览。

### C2. 构图控件（原计划的建议默认）

| 控件 | 行为 |
| --- | --- |
| 填满 cover（默认） | 保持比例铺满，允许裁切 |
| 完整显示 contain | 1 倍时展示整张图，允许留白 |
| 拖动／键盘定位 | 调整图在画布中的位置 |
| 缩放 | 所选铺放基准的 1–4 倍；contain 放大后允许裁切 |
| 重置 | 恢复该铺放方式的默认位置和倍率 |
| Apply / Cancel | 提交构图或丢弃草稿 |

用户确认了“只在导入时调整构图”；cover／contain 的具体组合、默认值和 1–4 倍是原方案建议，接手者应按此最小方案交付并明确这些默认值。

### C3. 保存与失败恢复

- 保存相对位置、铺放方式与缩放倍率；窗口／侧栏尺寸变化后按同一规则计算。固定的是构图参数，不是旧窗口的像素截图。
- 预览和应用后的显示使用相同计算。拖动、缩放不反复转换或重写 `.ans`。
- 草稿留在内存，Apply 后才写持久构图。构图与可重建的 SVG 缓存分离，缓存重建不能丢失用户构图。
- 最终文件与缓存就绪后才更新构图和选择。Apply 失败保留草稿和重试入口，当前选择不变；Cancel 回到原壁纸。
- 沿用现有原子发布、不覆盖目标、删除确认和异步草稿失效机制；两 Home 并行、连续选图、取消及转换中删除不能让迟到任务覆盖新选择或复活已删除文件。
- 没有构图记录的旧壁纸继续按原规则显示；删除对应壁纸时清理其构图记录。

### C4. 验收与首版边界

1. 新图片预览和最终保存均为 Dots；旧 Studio／Braille／Blocks `.ans` 正常显示。
2. 横图、竖图和方图在填满／完整显示下保持比例；拖动、键盘、缩放和重置符合说明。
3. Apply 后与预览一致；重开 Home、重启、换主题、调窗口／侧栏后构图参数有效，日常无法拖动编辑。
4. 回放 Cancel、Apply 失败重试、同名冲突、连续选图、两 Home 并行和转换中删除。
5. 在隔离桌面做真实拖动和缩放验收，留默认侧栏宽度的完整窗口证据。

首版不含平铺、拉伸、旋转、保存后重新编辑或历史壁纸批量转换。Home 久置后闪空白另属故障诊断，不混入本次构图需求。标题里出现过“深浅主题配置”，原始材料没有据此形成独立的新增主题需求；这里只保留现有主题切换下的显示要求。
